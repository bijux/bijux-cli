# Stability And Breakage

Stability policy is evidence-driven.

Stable surfaces:
- command identities and normalized routes that are parity-complete
- output envelope and exit semantics where parity gates pass

Breakage risk surfaces:
- parity-partial commands
- plugin lifecycle write paths under active hardening
- areas marked intentionally different but still under review

Before calling a release area stable, check:
- parity report
- runtime unity report
- docs audit and status artifacts
