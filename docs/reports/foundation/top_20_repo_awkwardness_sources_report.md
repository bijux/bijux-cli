# Top 20 Repository Awkwardness Sources

1. Large modules with mixed responsibilities.
2. Generated reports spread across partially overlapping names.
3. Governance configs split across many small files without central index.
4. Legacy test targets still discoverable without context.
5. Fixture duplication across suites.
6. Report and suite naming drift.
7. Uneven direct contract test density by subsystem.
8. Non-obvious mapping from ADR to verification suite.
9. Thin wrappers with little semantic value.
10. Inconsistent ownership metadata across product-critical files.
11. Historical report clutter without lifecycle tagging.
12. Multiple artifacts expressing similar system readiness signals.
13. Scattered command inventories across docs and tests.
14. Documentation clusters with overlapping responsibility.
15. Mixed style in report section structures.
16. Sparse cross-links between evidence families.
17. Redundant report generators in dev-dag surfaces.
18. Similar checklists in separate files.
19. Limited discoverability for canonical fixture sets.
20. Lack of one canonical map from goals to evidence and tests.
