# Bijux DAG as a governed workflow operating system

## Product positioning

Bijux DAG is positioned as a governed workflow operating system, not only an execution engine.

## Core abstractions

- workflow templates for ETL, ML training, validation-promote, and report generation
- typed subworkflow invocation with deterministic bindings
- workflow contract inheritance for organizational standards
- approval gates and deterministic human wait states
- event choreography for safe downstream workflow triggers

## Workflow portfolio governance

Workflows can be grouped into portfolios spanning DAGs, schedules, datasets, and policies.

Portfolio-level observability summarizes health across related workflows.

## High-assurance workflows

Critical workflow designation enables stronger scheduling, audit, and verification guarantees.

## Quality and verification

Quality gates can require dataset checks, artifact verification, and explicit approvals.

Continuous workflow verification certifies reproducibility and policy baseline adherence.
